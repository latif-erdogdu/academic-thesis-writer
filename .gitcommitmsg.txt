feat(record): thesis registry writable via single `record <REGISTRY> --file <json>` CLI command

New module `tools/atw/record.py` — unified registration writer for all 20
thesis registries. Key design:

- `record <REGISTRY> --file <json>` replaces 20 near-identical dedicated
  commands. New registry added by extending one table (not 20 new scripts).
- Validation order: JSON schema → identity (prefix, format, in-file duplicates)
  → new dangling references via `graph.kopuk_baglari` diff. No partial writes:
  all-or-nothing.
- `SAHIPLI_KOMUTLAR` registry list: owned by dedicated commands
  (`sources/search_runs`→`thesis:search`, `evidence_registry`→`cmd_extract`,
  `chapters/paragraphs`→`cmd_write`, `audit_registry`→`cmd_audit`). These are
  excluded from `record` to prevent bypassing their gate+schema checks.
- `yazilabilir_registryler()` derived from `graph.registry_haritasi()` — no
  hand-written table, so new schemas auto-appear.
- `KayitHatasi(ValueError)` collects ALL errors; CLI prints them all; partial
  state mutation never occurs.
- ID auto-generation via `ids.next_id()` when omitted; replaces invented
  numbering schemes.

Added `tests/unit_tests/test_record.py` (29 behavioural tests, network-free
via monkeypatched schemas, all-or-nothing assertion style).

Affected files:
- tools/atw/record.py (new, 242 lines)
- tools/atw/cli/main.py (parser entry + `cmd_record` handler, 80 lines added)
- tests/unit_tests/test_record.py (new, 29 tests)
